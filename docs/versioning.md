# 版本号规则

ProxyCat 统一使用 `主版本.功能版本.修复版本`（SemVer），例如 `0.13.0`。不使用日期版本、第四段版本号或前导零。当前仍处于 `0.x` 阶段；历史版本和标签保持原样，从下一次发布起执行本规则。

| 变更 | 递增规则 | 示例 |
| --- | --- | --- |
| 修复问题、性能优化、文案或样式调整，没有新增用户功能 | 修复版本 +1 | `0.12.4 → 0.12.5` |
| 新增用户可见功能（例如菜单栏状态颜色） | 功能版本 +1，修复版本归零 | `0.12.4 → 0.13.0` |
| 首次稳定版 | 发布 `1.0.0` | `0.x.y → 1.0.0` |
| 1.0 之后不兼容的配置、数据或公开接口变化 | 主版本 +1，其余归零，并提供迁移说明 | `1.3.2 → 2.0.0` |

`0.x` 阶段的不兼容变化递增功能版本，并在更新日志中明确说明。一个发布包含多类变化时取最高级别，只递增一次。开发过程中的每个提交不单独升版本。

## 走向 1.0.0

本轮功能版本为 `0.17.0`（构建号 13），包含 #10 的真实运行诊断与复检操作、#11 的订阅后台更新与安全配置应用、#12 的网站代理/直连偏好，以及可选的原生离线安装器。2026-11-14 用户确认本轮功能暂告完成，发布后以日常稳定性观察为主；开发期间的构建 10–12 均为未发布的内部验收包，不创建同版本的多个正式 Release。构建 13 将验收时补充的 HTTP 错误状态、失败原因透传和后台调度回归一起纳入正式安装包。

普通内核应用新配置时保留模式和仍有效的手选节点，失败时恢复旧配置并验证；无法确认恢复时撤下旧成功提示。TUN 会话只保存并显示待生效，不由后台更新主动切换接管方式。诊断报告保留检测时间，网络变化后降为历史记录并停用过期修复入口，不随每轮状态刷新消失。网站偏好独立保存，更新订阅后继续保留，应用后用实际请求、命中规则及节点链验证。

订阅后台更新已有 24 小时调度、失败后 30 分钟重试、并发保护、失败保留旧数据和应用回退的隔离回归。2026-11-14 的自然一天观察记录到两次尝试相隔 24 小时 4 秒，新配置应用成功；当前持久化记录没有单独区分手动与自动触发，因此成功时间变化本身不作为独立的来源证明。GeoIP 更新继续由 Mihomo 内置能力管理，最后尝试、最后成功和失败原因的界面展示按已确认的范围调整暂缓，不冒用文件修改时间，不纳入本次发布验收。

安装包同时保留“ProxyCat → 应用程序”拖动安装和下方可选的原生安装器。安装器等待旧版正常退出后替换、校验并打开，拒绝退出或超时则取消，不强杀应用或改变代理设置。最终发布包须通过本地回归、通用架构构建、只读挂载签名与布局检查；GitHub Actions 账户账单锁定时按发布文档执行本地验证，不把未启动的远程任务标记为通过。

随后进入日常使用观察期，暂停新增大功能，优先处理稳定性问题；需要修复时发布 `0.17.x`。重点观察普通代理与 TUN 切换、7890 就绪与恢复、退出清理、后台更新失败保留旧数据，以及网站偏好在订阅更新后保留。观察期限由实际使用情况决定，不预设发布日期；没有发现阻塞正常使用的问题，且已发现的问题完成回归后，由用户确认发布 `1.0.0`。首次稳定版不要求再凑一批新功能，也不需要先升到 `0.99.0`。

## 唯一来源

`app/ProxyCat/ProxyCat/Info.plist` 的 `CFBundleShortVersionString` 是用户版本号的唯一来源。Xcode 不再另存一套版本号；应用界面、DMG/ZIP 文件名和更新器都从该值读取。

`CFBundleVersion` 是内部构建序号：正整数，每次准备新版本 +1，永不归零，也不代替用户版本号。统一用脚本升版本，同时更新这两个值：

```bash
python3 scripts/version.py bump patch  # 仅修复
python3 scripts/version.py bump minor  # 新功能
python3 scripts/version.py bump major  # 首次稳定版，或稳定版后的不兼容变化
python3 scripts/version.py bump build  # 同一未发布版本重新打包，仅增加构建号
```

新增对应的 `docs/releases/vX.Y.Z.md`，使用“新功能”“修复”“改进”等标题，说明用户实际能感受到的变化。检查版本与更新日志：

```bash
python3 scripts/version.py check
python3 scripts/version.py check --tag v0.13.0
```

## 发布约束

- Git 标签固定为 `vX.Y.Z`，GitHub Release 标题固定为 `ProxyCat vX.Y.Z`。
- 标签、应用版本、更新日志文件名、安装包文件名、`update.json` 必须指向同一个版本；构建和发布检查自动拦截不一致。
- 新版本必须高于已有发布标签；发布后不重写标签、不替换同版本安装包。有问题就发布更高的修复版本。
- 当前更新器只支持正式的三段版本号。暂不把 `beta` / `rc` 版本放进正式更新通道；开发构建不创建正式 Release。
- 发布后先验证 GitHub 下载文件和应用内检查更新；本机安装由用户从应用内尝试，便于验证真实更新流程。
