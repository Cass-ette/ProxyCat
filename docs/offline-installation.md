# 离线安装与内部测试分发

从 0.17.0 开始，DMG 保留常见的“ProxyCat → 应用程序”拖动安装作为主入口，在下方提供可选的 `安装 ProxyCat.app`。新用户可照提示拖动，熟悉 Mac 的用户继续使用原来的方式；覆盖运行中的旧版时，也可双击安装入口，由安装器处理安全退出和替换，无需访问 GitHub。

安装器采用系统原生窗口、小猫应用图标、系统字体和标准按钮，自动适配浅色/深色外观。窗口显示安装包与已有版本，以及内部构建号，用户确认后才开始安装；较旧安装包会提示降级。检查和安装时显示当前进度，故障说明简短显示，技术详情默认折叠。

安装器具有独立标识 `com.cassette.proxycat.installer`，不会被正在运行的旧版 ProxyCat 当成“重新打开已有应用”。它首先验证旁边的 ProxyCat 身份、版本和代码签名，再请求现有 ProxyCat 正常退出，最多等待 45 秒并显示经过的时间。旧版退出回调负责系统代理、内核和 TUN 的清理；拒绝退出或超时就取消安装，不使用强制结束，也不直接修改网络设置。

复制先写入 `/Applications` 下的独立临时目录并验证，然后重新确认旧版进程已退出，才备份并替换目标应用。复制或目标校验失败会保留、恢复原有应用；若恢复本身失败，明确报告保留旧版的备份位置。安装器仅处理应用包，不访问订阅和设置目录。没有安装目录写权限时，通过系统管理员授权运行固定安装工作进程；用户拒绝授权就不安装。授权安装的候选应用归属原登录用户，避免以后应用内更新因 root 所有权失败，递归设置归属时不跟随符号链接。完成后以用户身份打开新版；打开失败时提示从“应用程序”启动，不声称已经运行。

应用内更新器继续只提取 DMG 根目录的 `ProxyCat.app`，不执行安装器，保留原有下载校验、备份、替换和重启流程。

正常打包使用 `dmgbuild`/macOS 磁盘服务，并在只读挂载后的原始路径上执行严格签名校验。不能直接交付 `hdiutil makehybrid -hfs` 的输出：它会给应用内部文件添加 FinderInfo，导致代码签名失败。若本地受限而手工封装，必须清理打包新增的 FinderInfo，再对最终挂载镜像执行相同校验。解压工具可能丢掉这些元数据，因此“解压后签名通过”不能作为 DMG 的交付依据。校验失败必须停止交付，不能放宽安装器的签名检查。

`bash scripts/test-installer.sh` 在临时目录测试首次安装、替换、复制校验失败、目标校验失败、移动失败回退、进程仍在运行、符号链接/无关目录保护、源包验证前不退出、拒绝退出/超时后不替换，以及安装命令参数转义。测试不退出本机 ProxyCat，不写 `/Applications`，不改变代理或 TUN。`scripts/build-installer.sh` 编译通用架构安装器，DMG 完整性检查同时验证主应用和安装器的架构、签名及版本。原生对话框、退出交接和管理员授权仍需在图形会话中实际验收。
